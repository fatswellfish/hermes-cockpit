# 需求变更 v2：四级级联的 todo

> 2026-11-23 用户逐条确认。取代 v1 的「三栏平铺」。
> 每条都挂用户原话或明确选择，不掺我自己发明的规则。

---

## 一、要解决的问题

**原话**：「todo 理论上来自各个 session，所以 session 展开后下一步应该是由于该确定的 session 引出的 todo，
至少也是这个 project 下的各个 todo，这个可以避免 session 溢出时新建 session 但是 todo 仍然未完成的情况」

⇒ session 会压缩、溢出后新建，但 todo 不能跟着丢。所以 todo 必须**独立于 session 存活**，
同时又能追溯当初是哪个 session 引出的。

---

## 二、最终结构（用户确认）

```
列1  项目
       └ 列2  会话
                └ 列3  人看的主条目        ← 要交付什么
                          └ 机器看的子步骤   ← 逐项推进，推动主条目进度
```

**三列够了**（用户原话：「这样 3 列就够了」）。第四层子步骤在列3 内部展开，不占独立列。

| # | 决定 | 出处 |
|---|---|---|
| 1 | 项目 → 会话 → todo，**项目层额外汇总一份**本项目全部 todo | 选择「项目→会话→todo，但项目层也汇总一份」 |
| 2 | **按类型分三份文件**：agent 自动化 / 办公日常 / 家庭 | 选择「按类型分文件」 |
| 3 | todo 里**存 session id**；没有 session id 的旧 todo **靠 project 兜底** | 选择「两者都要」 |
| 4 | 人看 = 主条目，机器看 = 其下子步骤，**子步完成推动主条目进度** | 选择「是。人看的是主条目…」 |
| 5 | 机器看的子步骤 **agent 自己写**（做完一步勾一笔），用户**只负责看** | 选择「agent 干活时自己往上写，你只负责看」 |

---

## 三、三份文件的职责

| 文件 | 谁写 | 内容举例 |
|---|---|---|
| `TASKS.agent.md` | **agent 自己写**（做完一步勾一笔） | 「Hermes Cockpit 第一版」及其 12 个子步骤 |
| `TASKS.work.md` | 人写，agent 可读 | 办公辅助、日常工作 |
| `TASKS.home.md` | 人写，agent 可读 | 家里要做的事 |

**家庭和日常工作属于「日常日志类」**（用户原话），可能联系到 agent 的部分——
即某条家庭 todo 可以由 agent 协助推进，但**条目本身归人**。

## 四、条目格式（草案，实现时定稿）

```markdown
## T-001 Hermes Cockpit 第一版 · doing · 0% · proj:hermes-cockpit
> session: local-41efc402...        ← 没有这行就靠 proj 兜底
> source: agent                      ← agent / work / home

- [ ] T-001.1 F1 适配层与边界扫描
- [x] T-001.2 A1 数据访问层

**快照**：设计基线已冻结，进入实现阶段
**阻塞**：无
```

进度 = 子步骤完成比例（复用现有逻辑）。

## 六、验收标准

1. 点项目 → 列出该项目所有会话 + 该项目全部 todo 汇总
2. 展开会话 → 只显示该会话引出的 todo
3. 展开 todo → 显示子步骤（机器看的）
4. 子步骤勾完 → 主条目进度条同步变化
5. **新建会话后，上个会话的未完成 todo 仍可见**（不随会话消失）
6. 三份文件各自可读可写，互不覆盖

## 七、与 v1 的关系

v1 的「三栏平铺（项目 / 会话·任务 / 详情）」**作废**。
v1 缺「按来源分三份文件」和「todo 挂到 session」，这两条为新增。
其余不变：只读 `projects.db`、绝不改 `sessions.cwd`、看板单向只读。

## 八、当前代码与此的差距（实测）

| 需求 | 现状 | 差距 |
|---|---|---|
| 三份文件 | 只认单个 `TASKS.md`（`store.py: TASKS_FILENAME`） | 要改成多文件聚合 |
| todo 挂 session | 解析器只读 `proj:` 字段 | 要加 `> session:` 解析 |
| 三级级联 | 前端是平铺三栏，无展开树 | 要重写列2/列3 的交互 |
| 主条目→子步骤 | 已有（`- [ ] T-001.1`） | 直接复用 |
