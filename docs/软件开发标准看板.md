# 软件开发标准看板（SDLC Board Standard）

> 2026-11-23 起草。目的：**不让主 bot 自己一个人把活干完**。
> 现状是规矩只写在 skill 里，没有强制；这份定下来后要找机制把它钉死。

---

## 一、为什么要这个

用户原话：「最近几项工作，明显你绕过了 designer，coder」。

实测事实（2026-11-23）：

| 事实 | 证据 |
|---|---|
| 三个 dev bot 都在 | `profiles/dev-designer` `dev-executor` `dev-reviewer` |
| 职责定义清楚 | Designer 出可机检 spec；Executor 照 spec 实现到测试通过；Reviewer 对 spec 找缺陷 |
| **但三个 bot 用同一个模型** | 全是 `qwen3.8-27b` @ `spark-vllm` |
| 最近的活没派给它们 | project-hub 从设计到测试全程主 bot 独自完成 |
| 14 个看板大多空置 | 说明这套流程早没跑起来 |

⇒ 缺的不是 bot，也不是职责定义，**缺的是「不按标准建板就干不了活」的机制**。

---

## 二、标准看板（软件开发专用）

### 必须有的五段卡，缺一不可

```
① 设计卡      assignee: dev-designer      产出 spec.json
      ↓
② 实现卡      assignee: dev-executor      产出代码 + 测试通过
      ↓
③ 审查卡      assignee: dev-reviewer      对 spec 找缺陷
      ↓
④ 修复卡      assignee: dev-executor      （审查不通过时才出现，可循环）
      ↓
⑤ 验收卡      assignee: dev-reviewer      全量验收，通过才 done
```

### 每段卡的硬要求

| 段 | 必含字段 | 缺了会怎样 |
|---|---|---|
| ① 设计 | `--skill` 指定设计方法；body 写清「验收标准」 | spec 不可机检 → 后两段全部白做 |
| ② 实现 | 依赖 ①完成（`--parent`）；`workspace: worktree` | 没有隔离工作区 → 改坏主线 |
| ③ 审查 | **必须** assignee = `dev-reviewer`；body 带 spec 路径 | 自己审自己 = 没审 |
| ④ 修复 | 依赖 ③；循环到审查通过 | — |
| ⑤ 验收 | 全量跑，不接受「大部分通过」 | 假绿 |

### 三个不可协商的点

1. **审查卡必须存在，且 assignee 不能是干活的那个 bot。**
   这是 `swarm` 已经强制的事（`--verifier` 是必填参数）。

2. **实现卡必须有 `--parent` 指向设计卡。**
   没有依赖就会出现「规格还没定就开始写代码」。

3. **同一张卡不许跨段复用。**
   设计和实现是两张卡，不是一个 bot 干两步。

## 三、已知的缺陷（必须一并解决，否则标准形同虚设）

### 缺陷 1：三个 bot 同一个模型 → 审查等于自审

Designer / Executor / Reviewer 全跑 `qwen3.8-27b`。同一模型换个身份，**判断偏好完全一样**，
它认为没问题的，换个称呼还是认为没问题。

⇒ 要么给 Reviewer 换模型（跨厂商），要么承认「审查」只是形式。

### 缺陷 2：绕过的成本比按规矩低

按标准走要建 5 张卡、等 3 个 bot、过 3 道转发；主 bot 自己干 20 分钟就完了。
**没有任何东西阻止它选便宜那条路。**

⇒ 需要机制，不是提醒。可用的手段（按强度排）：

| 手段 | 强度 | 代价 |
|---|---|---|
| `swarm` 建板（`--verifier` 必填） | 中 | 固定三角色，不是任意流程 |
| 插件钩子拦「无看板就写代码」 | 高 | 要写插件，且能被 `execute_code` 绕过 |
| 用户当场检验（问"板在哪、卡谁在做"） | 低但立刻可用 | 靠人盯 |

## 五、验收标准（本标准生效的判据）

1. 新建软件开发看板时，**没有审查卡就建不出来**（机制层拦，不是提醒）
2. 审查卡的 assignee ≠ 实现卡的 assignee
3. 实现卡的 parent 指向设计卡
4. 主 bot 独自完成一项软件开发工作、且没有对应看板 → 能被当场发现

第 4 条最难，也是最关键的一条。
