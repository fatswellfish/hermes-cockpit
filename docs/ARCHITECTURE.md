# Hermes Cockpit 架构说明

> 目的：让**没读过源码的人**也能理解这套东西怎么组成，以及**换一个 agent 时要替换哪一层**。
> 对应决策 D11：优先服务 Hermes；他人复用架构思路与数据格式，不兼容部分自行解决。

---

## 一、解决什么问题

一个 AI 助手（agent）用久了会产生四类互不相通的东西：

| 对象 | 是什么 | 典型问题 |
|---|---|---|
| **项目** | 一个工作空间，有名字和主目录 | 只能在命令行管；界面每项目只显示 3 条会话 |
| **会话** | 一次完整对话，靠 cwd 归到项目 | 大量会话挤在默认目录，不属于任何项目 |
| **任务** | 待办事项，可嵌套子任务 | 只在会话内存里，重启即丢，人看不到 |
| **看板** | 卡片式执行流，bot 之间派活用 | 与项目完全孤立，两套数据互不相通 |

**本插件的定位是「结果层」**：把执行中的碎片卷成「现在什么情况」，而不是再造一个执行器。
所以它**只读聚合**，不写回上游 —— 这是它跟「又一个看板」的根本区别。

---

## 二、四层关系（核心概念，与宿主无关）

```
┌──────────────────────────────────────────────────────┐
│  项目 Project                                        │
│  · 有主目录，是会话的归属锚点                        │
│  · 一个项目属于一个分类（单选，避免重复出现）        │
└───────────────────┬──────────────────────────────────┘
                    │ 归属解析：cwd 命中 > 手动标 > 无归属
                    ▼
┌──────────────────────────────────────────────────────┐
│  会话 Session                                        │
│  · 归属依据 = cwd 落在哪个项目目录                    │
│  · cwd 定不了的，用外挂映射表（session_map）补        │
│  · **只打标签，永不改会话内容，永不改 cwd**           │
└───────────────────┬──────────────────────────────────┘
                    │ 会话里产生的待办
                    ▼
┌──────────────────────────────────────────────────────┐
│  任务 Task                                           │
│  · 人机共写的 Markdown 文件，唯一写入口               │
│  · 可嵌套子任务；父进度由子任务完成比例自动重算       │
│  · 带快照/阻塞/截止，人一眼能看懂现在什么情况         │
└──────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────┐
│  看板 Kanban（单向只读聚合）                          │
│  · 插件只读它，把它卷成「几张在做/几张卡住」的计数    │
│  · **绝不写回** —— 避免两套真相源打架                 │
└──────────────────────────────────────────────────────┘
```

### 三条不可动摇的原则

1. **单向聚合**：插件是下游，永远不改上游。看板继续跑它的，插件只负责「让人看见」。
2. **归属只贴标签**：会话归属是**视图层**的标签，改标签不等于移动会话。
   （上游「移动到项目」在会话运行中会静默失败，所以根本不碰它。）
3. **未归属就静默**：解析不出归属时，不注入、不提醒、不改任何数据。宁可不说，也不骚扰。

## 三、归属解析（换 agent 时最需要照抄的一段）

优先级**写死**，不按场景变：

```
显式手动标(manual)  >  cwd 命中项目目录  >  关键词建议（未确认 = 视为无归属）
```

三者的落地：

| 来源 | 存在哪 | 什么时候写 |
|---|---|---|
| `cwd` 命中 | 宿主自己的会话表 | 宿主创建会话时 |
| `manual` | 自有映射文件 `session_map` | 用户在面板里点「归类到项目」 |
| `import-confirmed` | 同上 | 首启引导「导入已有」+ 逐条确认 |
| `suggested-confirmed` | 同上 | 系统给建议、用户点确认 |

**冲突规则**：手标与 cwd 指向不同项目时，**以手标为准**，并在界面提示二者不一致。

### 作用域（避免存量污染）

首次使用有两种模式，区别只在**看得见多少历史**：

| 模式 | 含义 | 作用域 |
|---|---|---|
| `fresh`（从零开始） | 不扫描历史 | 只看**安装之后**产生的会话（`started_at >= setup.at`） |
| `imported`（导入已有） | 接管存量 | 全量可见，但逐条确认才落库 |

`setup.at` 在首次完成引导时写入，**此后永不改变**。不提供 `imported → fresh` 反向切换
（否则插件自己产生的会话会突然出视野，验收也没法写）。

⚠️ **作用域必须同时约束读写**：`fresh` 下对存量会话不仅不显示，也**不能被归类**（越界返回 403）。

## 四、分层：换一个 agent 要替换哪一层

```
┌─────────────────────────────────────────┐
│  界面层  desktop-plugins/plugin.js      │  ← 换 agent 时【重写】
│  （三栏布局、点击跳转、勾选交互）        │     它依赖宿主 UI 框架
└──────────────────┬──────────────────────┘
                   │ 只调 HTTP 接口（ctx.rest）
┌──────────────────▼──────────────────────┐
│  路由层  dashboard/plugin_api.py        │  ← 换 agent 时【基本保留】
│  （GET /overview、POST /tasks/toggle…） │     纯 REST，不碰宿主
└──────────────────┬──────────────────────┘
         ┌─────────┴─────────┐
         ▼                   ▼
┌──────────────────┐  ┌──────────────────────────┐
│ 核心层            │  │ 适配层 host_adapter.py   │  ← 换 agent 时【重写】
│ core/taskfile.py │  │ （唯一宿主接触面）        │     所有宿主私有调用都在这里
│ dashboard/store.py│ │ · 读宿主库（只读）        │
│                  │  │ · 调宿主 RPC              │
│ 与宿主无关        │  │ · 版本兼容校验            │
│ 【原样保留】      │  └──────────────────────────┘
└──────────────────┘
         │
         ▼
┌─────────────────────────────────────────┐
│  数据层（纯文本，任何工具可读写）         │  ← 【原样保留】
│  META.yaml（分类/映射/引导状态）          │
│  TASKS.md（任务事实源）                   │
└─────────────────────────────────────────┘
```

### 一句话判据

> **换一个 agent，只需要重写「界面层」和「适配层」，中间的 REST 路由、核心算法、数据文件全部原样搬。**
> 适配层以下的兼容问题（那个 agent 的库结构、RPC 名字、hook 机制）由接手的人自己解决。

## 五、适配层契约（照这个实现就能接新宿主）

适配层必须提供下面这些函数，签名固定，内部实现随意：

| 函数 | 作用 | 换宿主时要做什么 |
|---|---|---|
| `hermes_home()` | 宿主数据根目录 | 改成新 agent 的数据根 |
| `open_ro(path)` | 只读打开宿主库 | 换成新 agent 的存储引擎（**必须只读**） |
| `columns(con, table)` / `pick_column()` / `require_column()` | 列名探测 | 换成新存储的 schema 探查方式 |
| `read_projects()` | 读项目列表 | 换成新 agent 的项目概念 |
| `read_sessions(limit)` | 读会话列表 | 换成新 agent 的会话概念；**时间字段必须归一成 epoch 秒** |
| `read_boards()` / `read_board_tasks(slug)` | 读看板 | 没有看板就返回 `[]` |
| `host_version()` / `compat_status()` | 版本与兼容区间 | 换成新 agent 的版本来源 |
| `create_session(cwd, ...)` | 在指定目录新建会话 | 换成新 agent 的建会话接口 |
| `session_cwd(session_id)` | 回查会话实际归属目录 | 同上 |

**两条硬要求**（换谁都得守）：

1. **列名一律探测，禁止硬编码**
   实测教训：那个宿主的会话表主键叫 `id` 不叫 `session_id`，时间列叫 `started_at`，
   **66 列里根本没有 `created_at`**。硬编码任何一个都会静默返回空 —— 比报错更难查。
2. **建会话必须让 cwd 真正落地**
   只传 `cwd` 不保证生效，很多实现有另一个显式开关（那个宿主叫 `cwd_explicit`）：
   `True` 才落地，`False` 会被 profile 默认目录覆盖。**建完必须回查库确认，不信返回值。**

### 连接生命周期：`with sqlite3.connect()` 不关连接

**这是换宿主的人必踩的一个坑。** Python 的 `sqlite3.Connection` 作为上下文管理器时，
`__exit__` 只**提交或回滚事务**，返回 `False`、**不关闭连接**：

```python
with sqlite3.connect("state.db") as con:
    con.execute("SELECT 1")
con.execute("SELECT 1")      # ← 照样能用：连接根本没关
```

实测（`py3.11` / `py3.10` 均为同一语义，不是某个版本的特例）。后果在 Windows 上最刺眼：
句柄一直挂在宿主库文件上，表现为「文件被占用」，插件卸载或升级时删不掉。

**必须写成 `try/finally: con.close()`**：

```python
con = open_ro(host_db())
try:
    ...
finally:
    con.close()
```

`open_ro()` 另外把连接登记在 `_OPEN_ROS` 里，插件卸载时由 `close_all()` 兜底释放
（`sqlite3.Connection.close` 在 py3.14 是只读属性，无法在实例上包一层幂等 close，
所以「重复关闭要静默」只能靠 `with` 只有一层 + `close_all()` 的 `discard` 约定）。

### 网关不是 HTTP 端口，别自造契约

实测那个宿主（0.23.2）的 `gateway_state.json` **没有端口字段**，`netstat` 上也没有
8000 在听；它对外是本地 **WebSocket**，客户端要先经控制 socket 换一张 session-ticket
才能连上。所以「读 `gateway_state.json` 的 port → 依次试 `/rpc`、`/jsonrpc`、`/api/rpc`」
是自造的契约，必然落在「读不到网关端口」这个分支上。

正确做法：**用宿主自己发布的客户端**（本宿主是 `hermes_cli.gateway_client.connect_gateway`），
把 RPC 名字与参数当成契约，而不是把网络形状当成契约。

⚠️ 还有一种**看起来像网关挂了**的假故障：`Gateway draining: update_paused`。
此时控制 socket 能连、能换票，只有**新会话准入**被关；同一个网关稍后重试就成功。

## 六、兼容性与降级

插件是宿主上的一个模块，宿主升级可能改库结构、RPC 名、hook 语义。三条防护：

| 防护 | 做法 | 验收 |
|---|---|---|
| **可检测** | `compat.yaml` 声明兼容区间，启动时比对一次 | 版本超区间 → 出现横幅 **且** 写入口禁用 **且** 宿主仍能启动 |
| **可隔离** | 宿主调用只出现在 `host_adapter.py`，由脚本扫描越界 | 在别处塞一行 `sqlite3.connect(state.db)` → 扫描报错指出行号 |
| **可回滚** | 插件异常 fail-open，不阻塞宿主启动 | 让插件抛异常 → 宿主照常开新会话 |

## 七、数据格式（跨工具可读）

自有数据**只有两个纯文本文件**，不引入数据库：

**`META.yaml`** — 配置与映射
```yaml
setup: {status: done, mode: fresh, at: 2026-11-21T23:00:00+08:00}
categories: [办公事务, 审核流程, 家庭提醒, Hermes 开发, 内容生产]
session_map:
  <session_id>: {project: <slug>, source: manual, at: 2026-11-21T23:10:00+08:00}
reminders: {enabled: false}
```

**`TASKS.md`** — 任务事实源，人机共写
```markdown
## T-001 标题 · doing · 40% · proj:<slug>
- [x] T-001.1 子任务
- [ ] T-001.2 子任务
> 更新：2026-11-21 22:30
**截止**：2026-11-30
**快照**：现在做到哪了
**阻塞**：卡在哪
```

**为什么不用数据库**：数据库只有装了这个插件的人能读；
Markdown/YAML 可以用任何编辑器打开、可以 grep、可以进 git、换 agent 后照样能用。
需要索引时用**可重建的派生缓存**，删掉不影响数据。

## 八、不做什么（同样重要）

- ❌ 会话合并 / 拆分（上游没有这个能力，产品文案也不得暗示有）
- ❌ 双向同步看板（会造出两套真相源）
- ❌ 自动执行归属建议（只出建议，逐条确认）
- ❌ 为其他 agent 提供现成适配器（只交付架构思路与数据格式）
- ❌ 改会话内容、改会话 cwd
